# Architecture Guidelines

## Layered Architecture Pattern

### Controller Layer (`controller/`)
**Responsibility**: Handle HTTP requests and responses
- Use `@RestController` and `@RequestMapping` annotations
- Map HTTP methods: `@GetMapping`, `@PostMapping`, `@PutMapping`, `@DeleteMapping`
- Delegate business logic to Service layer
- Validate input with `@Valid` on DTOs
- Return appropriate HTTP status codes
- Document endpoints with JavaDoc

**Key Classes**:
- `TodoController` - Todo CRUD endpoints
- `ReminderController` - Reminder management endpoints
- `NotificationController` - Notification triggering endpoints

### Service Layer (`service/`)
**Responsibility**: Implement business logic and orchestration
- Contain domain-specific business logic
- Use `@Service` and `@Transactional` annotations
- Access data through Repository layer only
- Handle exceptions and logging
- Perform DTO ↔ Entity conversions
- Maintain data consistency

**Key Classes**:
- `TodoService` - Todo business logic
- `ReminderService` - Reminder scheduling and management

### Repository Layer (`repository/`)
**Responsibility**: Data access and persistence
- Extend `JpaRepository` for CRUD operations
- Define custom query methods
- Use Spring Data JPA query derivation
- Minimal business logic
- Handle database transactions

**Key Classes**:
- `TodoRepository` - Todo data access
- `ReminderRepository` - Reminder data access

### Model Layer (`model/`)
**Responsibility**: Entity definitions and data structure
- JPA entities with `@Entity` annotation
- Proper column definitions with `@Column`
- Relationship mappings (if applicable)
- Lifecycle callbacks: `@PrePersist`, `@PreUpdate`
- Use Lombok: `@Data`, `@NoArgsConstructor`, `@AllArgsConstructor`

**Key Classes**:
- `Todo` - Todo entity with timestamps
- `Reminder` - Reminder entity with scheduling

### DTO Layer (`dto/`)
**Responsibility**: Data transfer between API and internal layers
- Use for request/response bodies
- Include validation annotations
- Keep separate from entities
- Convert using MapStruct or manual mapping

**Key Classes**:
- `TodoDTO` - Todo data transfer object
- `ReminderDTO` - Reminder data transfer object

## Data Flow

```
HTTP Request
    ↓
Controller (@Valid DTO)
    ↓
Service (Business Logic)
    ↓
Repository (Data Access)
    ↓
Database
    ↓
Entity
    ↓
Service (DTO Mapping)
    ↓
Controller (Response)
    ↓
HTTP Response (JSON)
```

## Package Structure

```
com.todoai
├── config/          - Spring configuration classes
├── controller/      - REST controllers
├── service/         - Business logic services
├── repository/      - Data access repositories
├── model/           - JPA entities
├── dto/             - Data transfer objects
├── mapper/          - Entity-DTO mapping (MapStruct)
└── ToDoAiApplication.java - Main application class
```

## Key Architectural Principles

1. **Separation of Concerns** - Each layer has a single, well-defined responsibility
2. **Dependency Inversion** - Depend on abstractions (interfaces), not concrete implementations
3. **Single Responsibility** - Each class should have one reason to change
4. **DRY (Don't Repeat Yourself)** - Avoid code duplication
5. **SOLID Principles** - Follow SOLID design principles
