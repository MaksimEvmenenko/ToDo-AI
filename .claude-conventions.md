# Coding Conventions & Standards

## Java Code Style

### Naming Conventions
- **Classes**: `PascalCase` (e.g., `TodoService`, `ReminderController`)
- **Methods/Variables**: `camelCase` (e.g., `getTodoById`, `todoList`)
- **Constants**: `UPPER_SNAKE_CASE` (e.g., `DEFAULT_PAGE_SIZE`)
- **Packages**: lowercase with dots (e.g., `com.todoai.controller`)

### Code Formatting
- **Line Length**: Maximum 120 characters
- **Indentation**: 4 spaces (not tabs)
- **Braces**: Opening brace on same line (Java convention)
- **Imports**: Organized, no wildcard imports

### Documentation
- **JavaDoc**: All public methods and classes
- **Comments**: Explain "why", not "what"
- **README**: Project documentation with examples
- **Code Examples**: Include curl commands for API testing

## Spring Boot Conventions

### Annotations & Frameworks
- **Dependency Injection**: Constructor-based DI with `@RequiredArgsConstructor` (Lombok)
- **Transactions**: `@Transactional` for service methods that modify data
- **Validation**: `@Valid` on controller parameters, annotations on DTOs
- **REST**: `@RestController`, `@RequestMapping`, method-level `@GetMapping`, etc.

### Class Organization
```java
@RestController
@RequestMapping("/api/v1/resource")
@Slf4j
public class ResourceController {
    // 1. Injected dependencies (private final)
    // 2. Constructors
    // 3. HTTP endpoint methods
    // 4. Helper methods
}
```

### Lombok Usage
- Use `@Data` for entities and DTOs
- Use `@NoArgsConstructor` and `@AllArgsConstructor` for entities
- Use `@RequiredArgsConstructor` for services (constructor injection)
- Use `@Slf4j` for logging

## REST API Conventions

### Endpoint Design
- **Base Path**: `/api`
- **Version**: `/api/v1`, `/api/v2`, etc.
- **Resource**: `/api/v1/todos`, `/api/v1/reminders`, etc.
- **Actions**: GET (list), POST (create), GET (detail), PUT (update), DELETE (delete)

### HTTP Status Codes
- `200 OK` - Successful GET, PUT
- `201 Created` - Successful POST
- `204 No Content` - Successful DELETE
- `400 Bad Request` - Invalid input
- `404 Not Found` - Resource not found
- `409 Conflict` - Constraint violation
- `500 Internal Server Error` - Server error

### Request/Response Format
- **Content-Type**: `application/json`
- **Encoding**: UTF-8
- **Case**: camelCase for JSON keys
- **Timestamps**: ISO-8601 format with UTC timezone

### Validation
```java
@PostMapping
public ResponseEntity<TodoDTO> create(@Valid @RequestBody TodoDTO dto) {
    // @Valid triggers validation
    // Return 201 with created resource
}
```

## Entity & DTO Conventions

### Entity Classes (JPA)
```java
@Entity
@Table(name = "todos")
@Data
@NoArgsConstructor
@AllArgsConstructor
public class Todo {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    @Column(nullable = false)
    private String title;
    
    private String description;
    
    @Column(nullable = false)
    private Boolean completed = false;
    
    @Column(nullable = false, updatable = false)
    private LocalDateTime createdAt;
    
    @Column(nullable = false)
    private LocalDateTime updatedAt;
    
    @PrePersist
    protected void onCreate() {
        createdAt = LocalDateTime.now(ZoneId.of("UTC"));
        updatedAt = LocalDateTime.now(ZoneId.of("UTC"));
    }
    
    @PreUpdate
    protected void onUpdate() {
        updatedAt = LocalDateTime.now(ZoneId.of("UTC"));
    }
}
```

### DTO Classes
```java
@Data
@NoArgsConstructor
@AllArgsConstructor
public class TodoDTO {
    private Long id;
    
    @NotBlank(message = "Title is required")
    @Size(min = 1, max = 255)
    private String title;
    
    @Size(max = 1000)
    private String description;
    
    private Boolean completed;
    private LocalDateTime createdAt;
    private LocalDateTime updatedAt;
}
```

## Testing Conventions

### Test Naming
- `test{MethodName}_{Condition}_{ExpectedResult}`
- Example: `testFindById_WithValidId_ReturnsCorrectTodo`

### Test Annotations
- `@SpringBootTest` - Integration tests
- `@Test` - Test methods
- `@Before`, `@After` - Setup/teardown
- `@Mock`, `@InjectMocks` - Mocking with Mockito

## Git Conventions

### .gitignore
- Maven: `target/`, `.classpath`, `.project`, `.settings/`
- IDE: `.idea/`, `.vscode/`, `*.swp`, `*.swo`
- OS: `.DS_Store`, `Thumbs.db`
- Build: `*.class`, `*.jar`, `*.war`

### Commit Messages
- Use imperative mood: "Add feature" not "Added feature"
- First line: 50 characters or less
- Reference issues: "Fixes #123"

## Performance & Security

### Performance
- Use pagination for large result sets
- Index frequently queried columns
- Use lazy loading for relationships
- Cache when appropriate

### Security
- Validate all inputs
- Sanitize data before database operations
- Use parameterized queries (JPA handles this)
- Implement authentication/authorization as needed
- Keep dependencies updated

## Common Commands

### Maven
```bash
mvn clean install          # Clean and build
mvn spring-boot:run        # Run application
mvn test                   # Run tests
mvn package                # Create JAR/WAR
mvn compile                # Compile only
mvn clean                  # Clean build artifacts
```

### Git
```bash
git add .
git commit -m "Add feature description"
git push origin main
```

### Testing API
```bash
# List todos
curl http://localhost:8080/api/v1/todo/list

# Create todo
curl -X POST http://localhost:8080/api/v1/todo \
  -H "Content-Type: application/json" \
  -d '{"title":"New Todo"}'

# Get specific todo
curl http://localhost:8080/api/v1/todo/1

# Update todo
curl -X PUT http://localhost:8080/api/v1/todo/1 \
  -H "Content-Type: application/json" \
  -d '{"title":"Updated","completed":true}'

# Delete todo
curl -X DELETE http://localhost:8080/api/v1/todo/1
```
